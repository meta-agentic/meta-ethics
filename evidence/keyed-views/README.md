# Keyed views re-identify

**Backs:** theorem "Keyed views re-identify" (ten assertions). Clause A2.

**What it computes.** A five-party roster in which the working state shows findings under one key per party. An ordinary party sees three things: that view, the attributed acts of power (including the public delegation scopes), and interim exclusions. The program runs four linkage attacks: the object scope, the exclusion on a cited matter, key linkage, and elimination. It then applies a mitigated view, with per-finding handles and object and time suppressed below k. The program is checked by `../checker/check.py`.

**Command:** `./run.sh` here, or `../run.sh --check keyed-views`.

**Expected result:** the program is stratified, has one model, and passes 10/10 assertions. The attacker exposes ann, bob and cat, three of the four other parties; dan has no findings. The mitigated view no longer exposes the object.
